# 標案 E39 · 塗裝線產出與能耗

**賽道**：地球　**分類**：表面處理　**難度**：進階　**預估時間**：90–120 分鐘
**適合誰**：製造、品保　**資料筆數**：2012 筆

---

## 一、痛點

烤爐吃電很兇，但每台車架分攤多少電費沒算過。

## 二、背景

這件事拖很久了，原因很單純：烤爐吃電很兇，但每台車架分攤多少電費沒算過。這次不求大系統，只要一頁能用的東西。

## 三、期望產出

算出單位產出的能耗 → 看出能耗異常的時段 → 換算成每台車架的成本

## 四、交付物

一頁能直接開的 HTML（單檔），做到：算出單位產出的能耗 → 看出能耗異常的時段 → 換算成每台車架的成本；外加一張系統架構圖，標出「資料從哪來、AI 在哪一步、人在哪一步把關」——工具不限，Mermaid、直接產 SVG、draw.io、Excalidraw 都可以。

## 五、驗收標準

1. 能載入附的 data.csv（共 2012 筆），畫面正確顯示筆數，不會因為髒資料整頁壞掉
2. 做到核心功能：算出單位產出的能耗 → 看出能耗異常的時段 → 換算成每台車架的成本
3. 至少有一個 AI 功能會動：讓 AI 把金額與數量換算成單位成本，並指出異常的月份

## 六、資料字典 · `data.csv`

| 欄位 | 說明 |
|---|---|
| `月份` | 這筆紀錄發生的日期。⚠️ 格式故意混用（`0615`、`6月15日`、`2026/6/15` 三種都有），要先統一才排得了序。 |
| `項目` | 製程／階段。適合看卡在哪一段。 |
| `金額` | 數值。⚠️ 有極少數幾筆小數點錯位（比正常大約 100 倍），算平均前先揪出來。 |
| `數量` | 數量。⚠️ 有極少數幾筆小數點錯位（比正常大約 100 倍），算平均前先揪出來。 |
| `比率` | 數值。⚠️ 有極少數幾筆小數點錯位（比正常大約 100 倍），算平均前先揪出來。 |
| `來源` | 備註。⚠️ 大部分是空的，有填的也很隨意 —— 但正是這欄最適合叫 AI 讀出重點。 |
| `單位` | 部門。適合看跨部門的差異。 |
| `客戶` | 對象名稱（供應商／客戶）。⚠️ 同一家可能有不同寫法，統計前先確認。 |
| `耗時分鐘` | 數量。⚠️ 有極少數幾筆小數點錯位（比正常大約 100 倍），算平均前先揪出來。 |

> 這份資料**故意是髒的**：日期格式三種混用、關鍵欄位約三成空白、3 筆整列重複、2 筆小數點錯位。先清再做。
